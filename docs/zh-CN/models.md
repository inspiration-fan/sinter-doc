# 模型与推理引擎

[首页](../../README.zh-CN.md) · [English](../en/models.md)

## 两种引擎

| 引擎 | 简介 | 当前状态 |
| --- | --- | --- |
| SinterLM | 以 Rust 与原生 Metal 实现的本地推理引擎 | 正在研发和扩大验证范围 |
| MLX Swift LM | 基于官方 MLX Swift LM 的 Apple Silicon 推理选项 | 兼容性取决于所用发行版及其依赖版本 |

格式可识别、模型能加载、输出正确和性能达标是不同条件。应用会按当前设备、引擎和模型配置判断可用性；不可用模型会显示原因。

## 当前开发范围

Qwen3 和 Qwen3.5 是当前开发的模型方向。SinterLM 已有 Qwen3 0.6B 部分配置的内部验证，但这不代表整个模型家族、所有上下文、所有量化格式或 Qwen3.5 4B 已通过公开发行验收。

正式版本将提供按引擎、模型、权重格式和设备区分的兼容表。

## 使用自定义或微调模型

通过「模型工厂」中的添加本地模型入口选择完整模型目录。目录通常需要：

- `config.json`。
- 完整 safetensors 权重及分片索引（如果使用分片）。
- `tokenizer.json` 和 `tokenizer_config.json`。

目录的名称无需与在线模型名称相同。单独的 LoRA adapter 不能作为完整模型加载，应先合并基础模型并导出所选引擎支持的完整格式。

CUDA FP8、GPTQ、AWQ、GGUF 等文件不能仅通过修改扩展名转换为 MLX safetensors。具体可加载格式以应用的兼容检查和对应版本说明为准。

## 内存与上下文

较大的模型、较长的上下文和不同引擎会占用不同内存。以应用实际兼容检查为准，不能只按权重文件的磁盘大小判断能否运行。内存不足时可以选择更小的模型或缩短上下文。
